# AGENTS.md

Guide for AI agents (and humans) working on **antares-sql.app**, the website of [Antares SQL](https://github.com/antares-sql/antares).
It is a static Nuxt site: the home, the downloads, a few Markdown pages and the web theme editor.

See also [DESIGN.md](DESIGN.md) for the visual language and the rules for UI changes.

## Stack

| Area | Tech |
|---|---|
| Framework | Nuxt 4 (`nuxt generate`: fully prerendered, no server at runtime), Vue 3 `<script setup lang="ts">` |
| Styling | Tailwind CSS 3 (`tailwind.config.js`, `@tailwindcss/typography` for Markdown pages) + SCSS ([assets/scss/main.scss](assets/scss/main.scss)) |
| Content | `@nuxt/content` 3 (Markdown in [content/](content/), collection in [content.config.ts](content.config.ts); needs `better-sqlite3`) |
| UI libraries | `vue-tabler-icons` (generic icons), `aos` (scroll fade-in), `vue-github-button`, `@vueuse/core` |
| Lint | ESLint 9 via `@nuxt/eslint` + `eslint-plugin-tailwindcss` (no stylistic rules) |
| Deploy | GitHub Actions [main.yml](.github/workflows/main.yml), **manual** (`workflow_dispatch`): lint, generate, publish `dist/` to `gh-pages` (`public/CNAME`) |

## Related repositories

They live next to this one (`../antares`, `../antares-nightly`) and are the source of truth for what the site shows:

- **[antares](https://github.com/antares-sql/antares)** (branch `develop`): the app. Its `README.md`, `CHANGELOG.md`, `AGENTS.md` and `DESIGN.md`
  say what the app does and how it looks. Every feature claim on the site must match them.
- **[antares-nightly](https://github.com/antares-sql/antares-nightly)**: only CI workflows that build `develop` every night.
  Releases are tagged `vX.Y.Z-nightly.N`, with `Antares-Nightly-<version>-win_x64.exe` and `Antares-Nightly-<version>-linux_x86_64.AppImage`
  (no macOS, no portable, no ARM). The latest 10 are kept.

## Layout

```text
app.vue                  Root: forces the dark theme, JSON-LD, AOS init; pages with definePageMeta({ bare: true }) skip header/footer
pages/
  index.vue              Home: hero video, About, feature cards (BaseCard), value blocks (BaseGrid), supported databases (BaseStepper)
  downloads.vue          Download tables per OS: GitHub releases API, fetched client-side
  theme-editor.vue       Web theme editor (bare page, its own look: it mirrors the app)
  [...slug].vue          Markdown pages from content/, plus 301 redirects of old URLs
components/
  Base*.vue              Site building blocks: BaseButton, BaseCard, BaseGrid, BaseStepper, page containers (see DESIGN.md)
  AppFrame.vue           Framed app video/screenshot (poster, plays while visible)
  DownloadPlatform.vue   Download column of one OS
  The*.vue               Header (sticky) and footer
  theme-editor/          Theme editor parts; AntaresIcon.vue draws the app icon set
content/                 Markdown pages (about.md, _privacy.md); _doc/ is excluded from the collection
libs/
  getOS.ts               Visitor OS, to highlight the right download column
  themeEditor/           Theme editor state, labels, samples; icons.json is GENERATED from the app (see below)
modules/sitemap.ts       Writes sitemap.xml after prerender (excludes the theme editor)
public/                  Static files: videos/ (home media), images/ (posters/, themes/, og.png), favicon, CNAME
scripts/videos/          Recorder of the home videos (see below)
```

## Commands

```bash
npm run dev        # dev server on http://localhost:3000 (only one per checkout: Nuxt refuses a second one)
npm run lint       # what CI runs before generating
npm run generate   # static build into .output/public (dist/ is a symlink to it)
npm run preview    # serve the generated site
```

There is no typecheck script (`nuxi typecheck` needs `vue-tsc`, not installed). Node >= 22.22.3.

## Data that comes from the app

- **Icons**: [libs/themeEditor/icons.json](libs/themeEditor/icons.json) is generated by the app, never edited by hand. After the icon set
  changes in `antares/src/renderer/libs/icons`, run in the antares repo
  `node scripts/iconKit.js ../antares-website/libs/themeEditor/icons.json` and commit the file here.
  Use it through [AntaresIcon.vue](components/theme-editor/AntaresIcon.vue): `name="table"`, `table+cog`, `table+off`, `brand:postgresql`.
  Database engine logos are always `brand:*` icons (`mysql`, `mariadb`, `postgresql`, `sqlite`, `firebird`, `sqlserver`, `duckdb`):
  a new engine logo is drawn in the app first, then exported.
- **Releases** ([pages/downloads.vue](pages/downloads.vue)): `useFetch(..., { server: false })` on the GitHub API, so nothing is prerendered
  and the tables fill in the browser. Stable is the first non-prerelease of `antares-sql/antares`, beta the first prerelease,
  nightly is `releases/latest` of `antares-sql/antares-nightly`. Assets are matched by file name regexes: when the app changes
  `artifactName`, update them. Rows without a matching asset are hidden. Unauthenticated API calls are limited to 60/hour per IP.
- **Feature texts** (home cards, About, stepper): check them against the app `CHANGELOG.md`/`README.md` before writing.
  The supported and coming databases follow the app README ("Currently supported").

## Home videos

The videos in `public/videos/` are recorded from the real app with [scripts/videos/](scripts/videos/), one scene file each:

| Scene | Output | Shown in |
|---|---|---|
| `main.cjs` | `main.webm` (whole window) | Hero |
| `schema-diagram.cjs` | `schema-diagram.webm` | Card "Simple, but complete" |
| `query-editor.cjs` | `query-editor.webm` | Card "Autocomplete or format your queries" |
| `import-export.cjs` | `import-export.webm` | Card "Import and export" |

Flow (from the antares repo, see its `run-app` skill for `appDriver.js`):

```bash
# in ../antares
npm run test:db:up && npm run test:db:samples     # docker test DBs with the sample databases
npm run compile                                   # the driver runs dist/
node scripts/appDriver.js start --fresh
node scripts/appDriver.js press Escape            # changelog modal of a fresh profile
node scripts/appDriver.js seed                    # debug connections
node scripts/appDriver.js eval "const w=require('@electron/remote').getCurrentWindow(); w.unmaximize(); w.setContentSize(1280,800); 1"
# keep 5 connections named Sakila (MySQL), Shop (MariaDB), Analytics (PostgreSQL), Bookshop (Firebird samples), Chinook (SQLite):
# rename and remove the others through the connections store (eval), then `open` Sakila, Shop and Analytics

# in this repo
node scripts/videos/record.cjs scripts/videos/main.cjs public/videos/main.webm
node scripts/videos/sheet.cjs public/videos/main.webm 2   # contact sheet PNG to review the take
```

- **Review every take** with the contact sheet before committing it: timing, cut-off elements, unwanted popups.
- **Update the poster** of a re-recorded video (`public/images/posters/<name>.webp`): extract a meaningful frame with the Playwright
  ffmpeg (`-ss <seconds> -frames:v 1 frame.png`) and convert it to WebP (quality ~0.8, e.g. through a canvas in Chrome).
  The hero poster also appears in `public/images/og.png`.
- **No personal data on screen**: neutral connection names, no paths with the account name (the import/export scene answers the
  file dialogs with `C:\Users\Public\antares-demo`), no real hosts.
- Default theme, window 1280×800 content size. Each video is about 12–22 s and below 2 MB.
- On Windows the PostgreSQL test port 55432 can fall in a range reserved by Hyper-V/WinNAT (`netsh int ipv4 show excludedportrange protocol=tcp`):
  start that container on another port with a compose override and edit the connection port.
- The recorder uses the `playwright-core` of the antares repo (`ANTARES_DIR`) and the ffmpeg downloaded by Playwright (VP8 only).

## Conventions

- **Commits**: Conventional Commits with a scope (`feat(downloads): ...`, `fix(home): ...`), in English. Single maintainer:
  no branch ceremony is needed, committing on the current branch is fine. Pushing and deploying are manual steps the maintainer decides.
- **Code**: 2 spaces, no semicolons, single quotes (as the existing files). Comments and UI text in English.
- **Tailwind**: utility classes in the template; custom classes only when a utility can't express it
  (`eslint-plugin-tailwindcss` flags unknown classes, the theme editor is exempt). Don't use classes of a palette that does not exist
  (e.g. `primary-*`, which the config does not define).
- Prefer the existing `Base*` components to new ad hoc markup; follow [DESIGN.md](DESIGN.md).
- Keep pages prerenderable: data that must be fresh (releases) is fetched on the client with `server: false`.

## Verifying a change

1. `npm run lint`.
2. Open the page on the dev server and look at it at desktop and phone width (the layout is mobile-first with `lg:` breakpoints).
3. For the downloads page, check the rows with the real releases (they load in the browser, not in the HTML).
4. Before a deploy, `npm run generate` must succeed (it also writes the sitemap).
